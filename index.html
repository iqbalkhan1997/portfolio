FinOps Platform Engineering RBAC

FinOps Platform — Cost, Inventory & Self-Service Provisioning

The problem: multi-cloud spend across AWS, Azure, and GCP had no single source of truth, and infra requests had no consistent path from "someone needs a server" to "it's approved, costed, and provisioned" — every step was manual and undocumented.

I owned the requirements and architecture for three connected surfaces: a FinOps tile (multi-cloud cost dashboards, budget & anomaly tracking, savings recommendations, and an AI assistant for natural-language cost queries), an Inventory tile (a live, drill-down view across 25+ resource categories on AWS and Azure, GCP scoped as a planned extension), and a Provisioning Infra tile — a self-service request workflow that auto-generates Terraform from an approved request and gates creation behind cost approval and RBAC before anything touches AWS.

Underneath, I shaped the data layer to match each workload's actual access pattern — ClickHouse for high-volume billing/cost analytics, PostgreSQL for transactional app and audit state, Redis/Valkey for session and cache workloads — and specified real-time AWS Pricing API integration so cost sheets never rely on stale, cached figures. Every module carries a full RBAC/permission model and audit trail.

Outcome: one platform giving finance and engineering the same real-time view of spend, with every infrastructure change traceable and cost-gated before it happens — not after.

Built via an AI-assisted, agentic development workflow — directed end-to-end with personal review of every change before it shipped.

Data Engineering ClickHouse Multi-Cloud

Multi-Cloud Billing Pipeline → ClickHouse

The problem: raw billing exports from AWS (CUR), Azure (FOCUS), and GCP arrive in different formats, on different schedules, with different quirks — Azure re-exports a full restatement of the month daily, AWS never includes a real FX rate, and tags/account names drift over time. Loading any of this naively risks double-counting or silently stale figures.

I engineered the pipeline that normalizes all three sources into one unified ClickHouse warehouse table — the single source every cost dashboard, budget check, and AI query reads from. Loading is checksum/manifest-based and incremental, so a re-run only ever processes new or changed files, which is what makes it safe to automate unattended.

The harder problem was data quality after the fact: FX-rate normalization for accounts with no native exchange rate, and reconciliation when a tag or account gets renamed. Both are corrected in place against already-loaded historical data — never a full re-ingest. The whole cycle runs on a cron-scheduled, lock-protected pipeline, with materialized views auto-refreshing summary tables as new rows land, and ClickHouse itself tuned (memory caps, swap, batched month-by-month mutations) so a large reconciliation run never takes the server down.

Outcome: a pipeline that runs unattended overnight, self-corrects data-quality issues without manual intervention, and has never required a full historical reload to fix a mistake.

Built via the same AI-directed workflow as the platform above, under my own review at every step.
